# 平台差异

CCNBSLib 的目标平台是 **CC:Tweaked**。如果你在 **CraftOS-PC 模拟器**上开发或测试，
下面几处行为与真实游戏不同，会影响听到的结果。

## 扬声器音高

| 平台 | `speaker.playNote` 的音高参数 |
|---|---|
| 真实 CC:Tweaked | **不校验**。0..24 之外的值原样交给客户端，由客户端已安装的扩展音域材质包发声 |
| CraftOS-PC 模拟器 | **只接受 0..24**，超出即报错并中断当前播放 |

**本库刻意不夹取音高**，越界音符原样送进扬声器。这是为了让扩展音域材质包真正
生效——如果在这里夹到 0..24，那些音符会静默变成错的音高，扩展音域就等于失效。

因此在模拟器上播放含越界音高的曲目会报错。**这是模拟器的限制，不是库的缺陷**：
同一首曲子在真实 CC:Tweaked 上配合扩展音域材质包可以正常发声。

## 一个扬声器每 tick 能发多少个音

扬声器把音符攒在缓冲区里，**每个游戏 tick（50 毫秒）最多播出 8 个 `playNote`**，
超出的部分被拒绝、不发声。`playSound`（自定义音效）更严：**每 tick 只允许 1 个**。

所以声部密集的曲子需要挂多个扬声器。`ccnbs.play` 在扬声器不够时会给出
`speakers` 警告码。

## 定时粒度

CC 的定时器精确到 **50 毫秒**（一个游戏 tick），这是音符调度的物理下限。节拍比这
更细的曲子无法逐音符精确还原，库对这类曲子给出 `tempo-clamp` 警告码。

## HTTP

命令行播放器 `nbsplay` 需要 HTTP 才能下载曲目。两个平台默认都开启，配置位置：

- **CraftOS-PC**：`<用户数据目录>/config/global.json` 里的 `http_enable`
- **真实 CC:Tweaked 服务器**：`computercraft-server.toml` 里的 `http.enabled`

## 自定义乐器

`.nbs` 里内嵌的自定义乐器（带音效文件路径的那种）**不会被播放**，会被拒绝并跳过，
库给出 `custom-instrument` 警告码。真实的扬声器只能播放原版乐器，以及扩展音域
材质包补上的音高。

## 鼠标点击

命令行播放器的**点击/拖动进度条跳转**需要 `mouse_click` 与 `mouse_drag` 事件，而这些事件
**只有高级硬件才会发出**：

| 电脑类型 | 发出 `mouse_*` |
|---|---|
| 高级电脑 / 命令电脑 / 高级海龟 / 高级掌上电脑 | **是** |
| 普通电脑 / 普通海龟 / 普通掌上电脑 | **否**——永远收不到 |
| 显示器（任何类型） | **否**——高级显示器发出的是 `monitor_touch` |

依据是 CC:Tweaked 的源码而不是文档措辞：鼠标输入由终端的**彩色**标志把关
（`UserComputerInput.java`，`mouseSupport = terminal.isColour()`），而彩色标志就是
电脑型号本身（`family != ComputerFamily.NORMAL`）。文档里那句括注读起来像「所有掌上
电脑都发」，但型号映射说只有高级的才发——**这里以代码为准**。

所以在普通电脑上：进度条照常显示、照常刷新，只是**点不动**。这是硬件事实，不是曲子的
问题，库因此不要求鼠标支持、也不为此报警告。
